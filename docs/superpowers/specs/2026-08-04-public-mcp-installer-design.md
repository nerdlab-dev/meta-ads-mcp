# 너드보드 Meta Ads MCP 공개 설치 도구 설계

## 목표

GitHub에서 누구나 설치 과정을 확인하고 실행할 수 있는 공개 npm 패키지를 제공해요. 설치 후 실제 Meta 광고 작업은 너드보드의 원격 MCP 서버에서 실행해요. 사용자는 너드보드 로그인, 구독 확인, Meta 계정 연결을 마쳐야 광고 도구를 사용할 수 있어요.

공개 저장소는 오픈소스 설치 도구예요. 너드보드 서버와 Meta 광고 비즈니스 로직을 오픈소스로 표시하지 않아요.

## MVP 범위

- 공개 저장소는 `nerdlab-dev/meta-ads-mcp`를 사용해요.
- npm 패키지는 `@nerdboard/meta-ads-mcp`를 사용해요.
- 대표 명령은 `npx -y @nerdboard/meta-ads-mcp@latest install`이에요.
- 자동 설치 대상은 Codex CLI와 Claude Code예요.
- CLI는 각 제품이 제공하는 `mcp add` 명령으로 `https://nerdboard.kr/mcp`를 등록해요.
- Cursor, Claude Desktop, ChatGPT 등 다른 클라이언트에는 수동 설정 안내만 보여줘요.
- 실제 도구 목록, Meta API 호출, 데이터베이스 접근, 광고 생성 로직은 패키지에 넣지 않아요.
- 너드보드의 기존 OAuth, 구독, Meta 계정 연결, Meta Ads 도구를 재사용해요.

## 제외 범위

- Homebrew 배포
- Go 또는 Rust 단일 바이너리
- 로컬 stdio 프록시
- CLI 자체 OAuth와 토큰 저장
- MCP 전용 요금제
- 일·주·월 사용량 과금 플랫폼
- 테넌트·계정·도구별 신규 기능 플래그 테이블
- 너드보드 서버 소스 공개

## 구성요소

### 공개 npm 패키지

패키지는 설치 명령 하나만 제공해요.

`install`은 다음 순서로 동작해요.

1. Codex CLI와 Claude Code 실행 파일을 찾아요.
2. 둘 다 있으면 사용자가 `--client`로 선택하게 하고, 하나만 있으면 해당 클라이언트를 사용해요.
3. 각 클라이언트의 조회 명령으로 `nerdboard-meta-ads` 등록 여부를 확인해요.
4. 등록되어 있지 않으면 각 클라이언트의 공식 `mcp add` 명령을 실행해요.
5. 이미 같은 URL이 있으면 변경하지 않아요.
6. 로그인과 연결 확인 방법을 출력해요.

지원하지 않는 클라이언트에서는 설정 파일을 추측해 수정하지 않아요. 원격 MCP URL과 수동 설정 문서 주소를 보여주고 종료해요. 공개 패키지가 JSON이나 TOML 설정 파일을 직접 해석하거나 저장하지 않아요.

### 너드보드 원격 MCP

기존 `https://nerdboard.kr/mcp`가 도구 정의와 실행의 단일 원장이에요. 공개 패키지는 도구 정의를 복사하지 않아요.

서버는 OAuth 토큰 발급 시점뿐 아니라 `tools/call` 실행 시점에도 구독 상태를 확인해요. 사용할 수 없는 경우 일반적인 오류와 함께 결제 또는 구독 재개 URL을 반환해요.

### 기존 온보딩 연결

새 온보딩 상태 머신을 만들지 않아요. 기존 로그인, 테넌트 선택, 구독, Meta 연결, 동의 화면을 `return_to` 값으로 이어요. 각 단계를 완료하면 원래 MCP 인증 요청으로 돌아가요.

## 데이터 흐름

```text
GitHub README
→ npx install
→ MCP 클라이언트에 원격 URL 등록
→ 너드보드 OAuth
→ 로그인·테넌트·구독·Meta 연결 확인
→ 기존 Meta Ads 도구 실행
→ Meta Graph API
```

CLI는 광고 요청과 Meta 토큰을 저장하거나 중계하지 않아요.

## 오류 처리

- 지원 클라이언트를 찾지 못하면 설치된 프로그램을 추측하지 않아요.
- Codex CLI와 Claude Code가 모두 있으면 임의로 하나를 선택하지 않아요.
- 동일한 서버 설정이 있으면 성공으로 처리해요.
- 이름은 같지만 URL이 다르면 기존 설정을 삭제하거나 덮어쓰지 않고 사용자에게 알려요.
- 제품의 `mcp add` 명령이 실패하면 종료 코드와 다음 확인 방법을 보여줘요.
- 지원하지 않는 클라이언트는 실패로 숨기지 않고 수동 설정 절차를 보여줘요.
- 서버의 미구독 오류에는 너드보드 결제 URL을 포함해요.

## 유지할 안전장치

- Meta OAuth state 검증
- 테넌트가 연결한 Meta 토큰만 사용
- 공용 Meta 토큰 대체 경로 금지
- `tools/call` 구독 재검사
- 광고 생성 기본 상태 `PAUSED`
- `dry_run`과 요청 멱등성
- 광고 작업 감사 로그
- 전체 쓰기 및 활성화 긴급 중단 설정
- 최소 요청 제한

## 테스트

공개 패키지는 최소한 다음을 자동 검증해요.

- Codex CLI만 있으면 Codex의 공식 `mcp add` 명령을 호출해요.
- Claude Code만 있으면 Claude의 공식 `mcp add` 명령을 호출해요.
- 두 클라이언트가 모두 있으면 명시적인 선택을 요구해요.
- 같은 설정에 다시 실행해도 추가 명령을 반복하지 않아요.
- 이름 충돌 시 기존 설정을 변경하지 않아요.
- 지원하지 않는 클라이언트에서 수동 안내를 반환해요.
- `--help`와 `--version`이 정상 종료해요.

너드보드 서버 변경은 기존 MCP OAuth 테스트와 Meta Ads 도구 테스트에 구독 만료 후 `tools/call` 차단 사례를 추가해요.

## 배포

초기 배포 채널은 npm 하나만 사용해요. GitHub Actions에서 테스트가 통과한 태그만 npm에 배포해요. README에는 공개 CLI가 너드보드 관리형 서버를 사용하고 계정과 구독이 필요하다는 사실을 명확히 표시해요.

Homebrew와 단일 바이너리는 npm 설치 이탈이 실제로 확인된 뒤 검토해요.

## 완료 기준

- 공개 저장소에서 설치 방법과 서비스 경계를 이해할 수 있어요.
- 한 번의 `npx` 명령으로 Codex CLI 또는 Claude Code에 원격 MCP가 등록돼요.
- 공개 패키지가 제품 설정 파일을 직접 수정하지 않아요.
- 설치 패키지에 너드보드 서버 코드, Meta 토큰, 데이터베이스 정보가 포함되지 않아요.
- 미가입 또는 미구독 사용자는 너드보드 가입·결제 경로를 확인할 수 있어요.
- 가입, 구독, Meta 연결을 마친 사용자는 기존 Meta Ads 도구를 사용할 수 있어요.
